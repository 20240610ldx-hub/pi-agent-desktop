# Pilaude 目标锚点

本文件回答"为什么做、做成什么才算完"。任务卡的目标必须能追溯到这里的某个 Epic。本文件受保护：只有用户确认后，规划者才能修改。完整的用户访谈记录见 [Intent](../superpowers/specs/2026-10-16-pilaude-intent.md)，工程细节见 [Spec](../superpowers/specs/2026-10-16-pilaude-spec.md)，原始工作包见 [Plan](../superpowers/plans/2026-10-16-pilaude.md)。三者有冲突时，以用户最新的明确表述为准，并回写到这里。

## 北极星

Pilaude 是一个 MIT 开源、本地优先、Windows 优先的桌面通用工作智能体。内核是 Pi，界面和交互以 Windows 稳定版 Claude Desktop 为最高参照。用户自带 API Key 或提供商账号，围绕项目完成代码、文件、研究和内容任务。

**项目目的**：作品集与开源影响力。所以衡量成功的是两件事：真实用户能装上用起来，以及代码和工程过程经得起公开审视。

## 用户已确认、不可由 agent 更改的决定

- 首发范围**不砍**：多代理、定时任务、受控浏览器、丰富扩展（含用户指定的八个包）、Windows 正式发布门槛全部保留（2026-10-19 再次确认）。
- 面向开发者与熟练 AI 用户；简体中文、繁体中文、英文；本地优先，不需要 Pilaude 账号。
- 按项目授权：工作区内常规操作自动执行，删除、越界访问、对外提交需确认。
- 关窗进托盘继续运行；明确退出时终止任务；重启保留记录，可手动恢复。
- 每个组件以 Windows Claude Desktop 2.42304.0 为参照逐状态对照；只接主题或功能可用不算复刻通过。
- 付费测试只用 `deepseek-flash`，控制次数；重复回归用本地夹具。
- 保留 MIT 许可和上游署名；两个 fork 持续跟进上游。

## Epic 与完成的定义

每个 Epic 的"完成"由下面的可观察结果定义，而不是由提交数或测试数定义。任务卡拆的是通往这些结果的步骤。

| Epic | 内容 | 完成的定义 |
| --- | --- | --- |
| E0 | 工程基础与接力 | 主 checkout 干净；每项在途工作都有任务卡和分支；`npm test`、`tsc`、`lint` 有可信的绿色基线，已知失败逐条登记成卡 |
| E1 | 产品与更新身份 | UI、窗口、托盘、安装包、单实例标识都是 Pilaude；没有自有签名时不回退上游更新通道 |
| E2 | 界面复刻 | 每个组件有同版本参考图、实现截图和差异记录；交互（输入法、滚动、焦点、缩放、长会话、深浅色）逐项核验 |
| E3 | 本地数据与凭据 | 独立数据根；凭据用 DPAPI 加密；导入可选、先备份；日志与事件脱敏 |
| E4 | 统一执行前授权 | 拒绝或待批时执行计数为 0；直接、嵌套、MCP、子代理、定时任务的工具调用都经过同一授权门 |
| E5 | 受控浏览器 | 可见的专用 Chromium；导航、阅读、点击、输入、下载、取消、人工接管可用；未审批的提交和上传计数为 0 |
| E6 | 多代理 | 并行上限、深度上限、父子取消传播、撤权、重启后中断标记都有端到端验证；父子之间不能提权 |
| E7 | 定时任务 | 时区和夏令时、睡眠补跑、去重、不重叠、隐藏窗口审批都有假时钟测试；默认只读 |
| E8 | 扩展 | 安装、启停、卸载、失败回退可用；八个指定包各自有真实 consumer 和实际验证（见 E8 的任务卡） |
| E9 | 生命周期与恢复 | 关窗只隐藏，退出不留子进程；崩溃重启后状态可恢复，不自动重发 |
| E10 | 首次使用与帮助 | 新用户安装后不开终端，就能接入自己的模型并完成一次真实任务；帮助覆盖托盘、权限、浏览器、扩展、恢复 |
| E11 | 正式发布 | Windows 10/11 干净机器的安装、升级、卸载、DPI、2 小时耐久验证通过；有自有签名和更新密钥；缺外部材料时只发开发构建并列出未达门槛 |

## 不在首发范围

Pilaude 云账号、托管计费、云同步、企业管理、移动端、Linux 和 macOS 正式发布、自建插件商店、应用退出后仍运行的后台服务。保留上游已有能力，但不要求删除兼容代码。

## 优先级的含义

- **P0**：阻塞其他任务或威胁仓库健康（脏工作树、测试基线、安全问题）。
- **P1**：首发必需，且其他 Epic 依赖它。
- **P2**：首发必需。
- **P3**：打磨、残差、可以在首发后补。
