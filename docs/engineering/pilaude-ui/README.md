# Pilaude UI 工程工作台

此目录是 Pilaude UI 复刻任务跨会话、跨线程的接续入口。聊天上下文、子 agent 报告和提交说明不能替代这里的当前工程状态。

## 必读顺序

1. [交接状态](handoff.md)：当前任务、已做工作、未完成项、源码冻结范围和准确的下一步。
2. [计划](plan.md)：目标、优先级、验收出口及用户已决定的约束。
3. [进度与证据](progress.md)：已验证检查点、失败记录和证据范围。
4. [技术规格](technical-spec.md)：领域模型、数据链路、布局合同和实现边界。
5. 按工作区域补读仓库 `AGENTS.md`、`docs/agents/fork-*.md` 和相关 ADR。

详细历史与原像素残差继续保留在 [复刻基准](../../pilaude-ui-parity.md)、[组件采用账本](../../pilaude-component-adoption.md)、[Agent 输出清单](../../pilaude-agent-output-ui.md)。本目录维护当前决策和交接状态，不复制这些文件的全部历史。

## 持续维护规则

- 开始工作先读 `handoff.md`，再用实际源码、`git status`、HEAD 和服务状态核实其中的可变信息；不要重复已完成的调查。
- 用户补充或纠正要求时，在继续相关实现前更新 `plan.md`／`technical-spec.md`；旧验收不再适用时，在 `progress.md` 明确撤回其范围。
- 每个纵向切片按具体失败 → 最小实现 → 定向回归 → 实际页面 → 参考核对推进；每次状态实质变化更新 `handoff.md` 与证据表。
- 提交、推送、阶段交接和会话结束前，更新 HEAD、当前未提交文件归属、验证结果、仍失败的步骤及下一条可执行动作。只有实际完成的动作才能记为完成。
- 新接手者继续当前优先级；不能因为换线程重新列方案、重复请求既有授权，或把检查点当成“完全复刻”完成。
- 未完成的独立切片保留原改动并记录，按文件显式 staging，禁止用 `git add .` 混入未验 WIP。
- 用户最新要求是同时验收组件的大小比例关系和深层功能／UX。参考与实现需在同一帧／相同状态列出组件宽高、相对比例、间距、文字基线和对齐轴；已知DPI／缩放与未知项分开，不靠单个尺寸相同推定整体对齐。
- 实际验收包括状态变化、键盘／IME、焦点、草稿、历史／分支、重连、错误／取消恢复与副作用；截图只覆盖可见状态，不能代替这些路径的证据。
- 优先使用现有产品资源、upstream实现和成熟库；机制不确定时查官方网络文档，记录URL／版本、采用或不采用的原因及真实consumer。只有真实产品消费点与对应证据才可更新采用账本。功能通过、浏览器通过、Windows 原生通过和视觉一致分别记录。
- 私人截图、个人字体、custom stylesheet／data font、凭据与原始会话历史不放入本目录或公开提交。原件和派生图仅保留在忽略目录；工程文档只写机制、量测和证据位置。

用户要求当前主 agent 只负责协调、评审、验收和保存检查点；具体实现交给 3–8 个子 agent，处理用户反馈时例外。文档维护也可指定子 agent 负责，主 agent 审阅后接收。各 owner 的冻结报告必须包含准确文件、可复现命令、实际运行结果和剩余问题；同一 preview 的实际浏览器检查串行执行，源码冻结与实际通过分别记录。临时 agent ID 只服务当前会话，换线程从落盘状态接手，不等待失效 owner。
