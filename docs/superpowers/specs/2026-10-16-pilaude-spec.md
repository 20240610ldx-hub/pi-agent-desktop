# Pilaude Product and Engineering Spec

日期：2026-10-16。状态：访谈后的实现基线 v1；用户要求见 [Intent](2026-10-16-pilaude-intent.md)，执行顺序见 [Plan](../plans/2026-10-16-pilaude.md)。本文件定义目标行为，不声明这些能力已经交付。

## 1. 决策来源及代码基线

`Ixx` 为用户明确要求；`Exx` 为工程决定。未填写的自由补充不构成额外约束。

- Pi 工作树基线：`2ef31f03c3e6e01660aaf4b61af94487f9f4131d`，分支 `fusion/pi-claude-desktop`。
- UI 参考基线：`fb1eceb5891ba201138456347663ef702db47e3a`，上游源 `Caho1/open-claude-ui`。
- 现有 Pi 包含会话/SSE、子代理、调度器、MCP、skills、插件、Tauri 窗口与安装器。现有 `BrowserPanel` 是 iframe 浏览，不等同于受控浏览器自动化。
- 原有项目 trust 主要控制项目资源加载；不能据此宣称任意 Shell、插件或子进程已被限制在项目目录。
- 维护规则：保留 `app/globals.css` / `app/settings.css` 上游基线；新增主题进入 `app/native-theme.css`；变更共享文件时维护 `scripts/fork-ownership.json` 和相关哨兵测试。

## 2. 桌面框架决定（E01）

| 路线 | 本项目中的收益 | 成本与未验证项 | 结论 |
| --- | --- | --- | --- |
| 沿用 Tauri + 系统 WebView + 已捆绑的 Node 服务 | 复用原生菜单、托盘、安装器、进程管理和已有 UI/API；保留 Pi 适配 | WebView 差异、浏览器引擎另行打包、真实包体和内存仍需实测 | 第一阶段采用 |
| 改用 Electron + Chromium + Node | 渲染引擎统一，可使用 Electron 窗口 API | 需要迁移现有 Rust/IPC/菜单/安装/升级实现，已有桌面回归测试不能直接证明迁移正确 | 保留为测量不达标后的替代方案 |
| 全原生 UI + Pi 进程 | 平台控件整合更直接 | 大量 React 组件和会话界面需重写；跨平台维护面扩大 | 首发不采用 |

这是一项可回滚的工程决定，不声称 Tauri 完整应用必然比 Electron 更小或更快。若发布构建无法满足第 12 节，先定位瓶颈；若根因为 WebView/集成能力且局部修复不可行，记录同一验收集下的 Electron 原型对比，再修改决定。

官方资料已核对：[Tauri 架构入口](https://v2.tauri.app/start/)、[Tauri 权限](https://v2.tauri.app/security/permissions/)、[Electron 安全模型](https://www.electronjs.org/docs/latest/tutorial/security)。当前会话未提供 Context7 MCP，使用这些官方文档作为替代。

## 3. 产品身份、平台与发布隔离（I03/I11/I12；E02）

- 用户可见名称 Pilaude；发行名 `pilaude`；发布仓库 `20240610ldx-hub/pi-agent-desktop`，与代码 fork 地址保持一致。
- 第一份 Pilaude 开发版本为 `0.1.0`，存入独立的 `src-tauri/pilaude-package.json`，并与本发行的 Cargo 版本一致，不继承上游 Pi Agent 的发行版本号；原 `pi-agent-desktop-package.json` 保留作为上游组件版本，Pi SDK、pi-web、Pi 桌面上游的来源在组件清单中另行保留。清单 `appVersion` / `distribution` 表示 Pilaude，`components` 表示来源组件，不能混作同一个版本。
- 独立应用标识 `io.github.20240610ldx-hub.pilaude`；与原 Pi Agent 的窗口状态、单实例锁、安装和更新身份隔离。Rust crate / npm 上游包名不为改品牌而无必要地重命名。
- 正式支持 Windows 10 22H2 x64 / Windows 11 x64，使用已验证的 WebView2；Windows ARM64 不在首发保证范围。macOS 兼容代码保留，后续单独验收与发布。
- 中英文均完整；现有繁体中文不删除，新共用键同步维护以满足现有 i18n 合同。用户内容、工具输出和服务端原始错误不强制翻译。
- `main` 继续跟进上游；融合分支产生 Pilaude 构建。继承的签名材料、更新公钥、发布地址和证书不得冒充 Pilaude 的信任链。开发构建没有配置自有签名时禁用自动安装更新；不得回退原作者更新通道。

## 4. 信息架构和 UI 体验（I02/I04；E03）

主窗口：左侧项目与会话树，中间会话/任务主区，右侧文件、产物、Diff 与受控浏览器上下文。计划任务、代理管理、扩展和设置可从固定导航进入。运行状态、待授权数量和后台任务在主窗口与托盘之间一致。

默认窗口 1280×840，最小 960×640。窄于 1100 CSS px 时右侧上下文以覆盖面板展示，不压缩主输入区至不可用。Windows 使用 Windows 控件和拖拽规则，不绘制假 macOS 红绿灯。

主题以 UI 仓库的实际 CSS/组件和 v2 文档为参考；令牌通过 Pilaude 主题层映射，不能混用同名但数值不同的文档令牌。记录复用模块与来源 SHA。只移植/导入浏览器可运行部分，不从 UI 根入口引入 Electron 工厂。

必须覆盖：深浅色/跟随系统、100/125/150/200% DPI、键盘导航、可见焦点、减少动效、长路径/中英文混排、模态焦点恢复、可复制代码与工具输出。不得依靠颜色独自表达运行状态。

输入和流式行为：

- 输入法合成中的 Enter/Escape 不误发送、不关闭上层窗口；Enter 发送、Shift+Enter 换行。
- 一次发送仅产生一次请求；请求未被服务端接受时恢复草稿；已接受后断线不得自动重新发送。
- 用户离开底部阅读时不抢滚动；显式“跳至最新”恢复跟随。切换会话保留各自草稿和阅读位置。
- 模型、思考强度、Token/费用、工具卡片均来自真实运行状态；未知值显示未知，不填充演示数据。
- 工具状态由执行层驱动：`queued → awaiting_approval → running → succeeded/failed/cancelled/interrupted`；不适用审批时可跳过 `awaiting_approval`。点击允许不代表已经执行成功。

## 5. 模型、本地数据与凭据（I07/I08；E04）

支持 Pi SDK 已提供的提供商/API Key/OAuth 方式；自定义兼容接口保存 base URL、模型 ID、能力与鉴权配置，验证错误保留可修复信息。用户自行提供并支付模型服务；测试默认使用本地假服务，不擅自消耗真实额度。

默认数据根 `<platform-app-data>/Pilaude/agent`，在创建 SDK 服务之前传入；不修改进程级 HOME。不自动读取或覆盖 `~/.pi/agent`：提供用户发起的副本导入，预览来源、目标、冲突和备份。可选兼容模式须明确选择，不能静默切换。保留 JSONL 和未知字段，不就地改写旧会话格式。

凭据保留在本地后端；不经状态接口、SSE、错误摘要、浏览器快照和日志回传明文。Windows 发布版通过 DPAPI 保护的本地凭据存储接入 SDK，用户显式提供的环境变量只作为输入，不写入前端配置。DPAPI 由本地 Node 后端通过受控的隐藏系统调用适配，秘密只走子进程 stdin，不能进入命令行或新增 renderer 读取凭据的 IPC。开发适配器未完成加密时不能标为正式版。

默认不上传会话、文件或诊断。模型调用和用户批准的扩展/浏览器请求仍会访问相应服务，界面准确说明这一点。备份/导出默认排除凭据与浏览器 cookies；导入不执行项目代码或安装插件。

## 6. 执行权限（I09；E05）

所有模型工具调用在真实副作用发生前经过后端策略，包括直接工具、Code mode 嵌套调用、MCP、子代理与计划任务。UI 卡片不是安全边界。

| 操作 | 默认决定 |
| --- | --- |
| 未授权项目中的读写/运行 | 等待项目授权 |
| 已授权根目录内的结构化读取、列表、创建、编辑 | 自动，受路径校验和任务权限约束 |
| 删除、覆盖非本轮产物的不可恢复操作、越界访问 | 展示具体目标，逐次确认 |
| 对外提交、Git push、发布、上传文件、提交表单/消息、购买 | 展示目标与内容，逐次确认 |
| 已验证无副作用的内置只读命令 | 按参数化调用自动执行 |
| 任意 Shell、仓库脚本或无法判定副作用的命令 | 先确认具体命令；不能因 CWD 位于项目内而自动认定安全 |
| 插件/MCP 安装、执行本地第三方扩展 | 用户显式授权来源和能力；不由网页/模型自行给予信任 |

路径按 Windows 大小写/UNC、`..`、符号链接/junction 的实际目标校验；不使用字符串前缀判断。项目重命名/删除、根目录被替换、授权撤回时重新检查。审批绑定 task/session/tool-call、参数摘要和策略版本；参数变化、取消、重启或撤权使旧审批失效。批准一次只能消费一次。

这是受控工具的授权模型，不承诺在同一操作系统用户下隔离恶意任意插件或用户主动批准的 Shell。完整 OS 沙箱未完成前不得作这种产品宣称；受信任第三方扩展超出托管工具边界的宿主权限必须在安装时说明。

不对一般工具提供绕过所有敏感操作的“永远允许”。后台待审批暂停该操作并通知，未批准不产生副作用；15 分钟无响应标记过期并允许从会话重新发起，不循环弹窗。

## 7. 多代理协作（I06；E06）

复用内置 Agent、结果收集、steer/resume 和配置档。任务树展示父子关系、角色、模型、运行状态、可追溯结果和费用；不把内部系统通知当成人类指令。

默认全局最多 4 个活动 agent，根任务计入额度；最大派生深度 2。超额进入队列，用户可停止排队任务。子代理的根目录、工具、浏览器会话和可用审批不高于父任务；父级撤权/停止向后代传播。预防重复结果、陈旧 resume 通知和重启后永远等待。

同项目写操作通过任务级写租约协调；默认只有持有租约的任务可写，其他任务等待或在显式 worktree/副本工作。不能把 UI 中“负责的文件”当作并发写锁。父任务可选择只停止一个子任务或停止整棵树；执行状态与子进程实际结束一致。

## 8. 定时任务（I06/I10；E07）

复用现有任务存储、租约、独立会话与运行历史。支持一次、每小时、每天、每周和自定义 cron；任务记录 IANA 时区，编辑时预览下一次时间，DST 使用所选调度库的明确规则并测试。

仅应用进程存活时运行，包括窗口隐藏。明确退出期间不运行，不安装后台服务；睡眠唤醒/下次启动时每个任务至多补跑一次，积压多次合并为一次，并记录补跑。相同任务不重叠执行，全局额度与交互任务共享。

默认只读。可在创建任务时授权工作区内结构化写入；删除、越界和对外提交仍需该次审批。隐藏窗口遇到审批暂停并通知，不能借定时授权获得全工具权限。允许取消本次运行、禁用将来运行、删除任务但保留已执行会话与可导出记录。

## 9. 浏览器操作（I06；E08）

采用本地 Node 托管的 Playwright Chromium 专用可见浏览器，作为与应用 WebView 分离的执行进程；不把外站装进具有应用 IPC 权限的 renderer。使用与 Playwright 版本匹配的引擎；安装包携带或安装阶段显式获取并校验，离线缺失时说明原因，不伪造成功。

首发覆盖真实导航、文本/页面快照、截图、点击、输入、滚动、标签页和下载；用户可打开受控窗口手动登录或接管。配置档属于 Pilaude 的项目浏览器环境，不自动附着日常 Chrome、不导入其登录状态；cookies 按用户选择保留，可清除。

项目级域名授权；禁止模型任意进入 localhost、私网、`file:` 和调试端口，除非用户针对具体本地目标授权。登录/验证码由用户处理，不读取密码输入框或把 cookies/token 给模型。观察授权不代表有权上传或提交。

DOM 点击/键盘可能触发不可辨别的外部行为，因此不能宣称仅识别按钮文字就能保证无副作用：只读模式仅提供导航/观察，不暴露通用点击输入；交互模式对点击、输入、快捷键和上传提供具体动作审批，允许用户显式接管。可审计的内置适配器可将已验证的无副作用动作自动化；不为整个站点授予无条件提交权限。

审批等待不重复动作。页面改变导致定位不唯一/目标失效时重新观察，不扩大为任意点击。超时、崩溃、关闭窗口、下载取消和应用退出可传播取消；由本应用创建的浏览器进程必须被回收。

资料：[Playwright 浏览器管理](https://playwright.dev/docs/browsers)、[隔离的 browser contexts](https://playwright.dev/docs/browser-contexts)。浏览器包增加整体安装体积，不从 Tauri 的最小包体推导本产品大小。

## 10. 扩展（I06；E09）

首发“丰富扩展”具体指：SDK 支持的 skills、Pi 扩展包、MCP（stdio 与受支持 HTTP/OAuth）均可发现/手动添加、安装、启停、更新、卸载、查看来源与错误。复用现有搜索和管理能力，不承诺自建商店或兼容任意其他产品的插件协议。

配置解析保留未知字段；项目扩展发现不等于执行授权；秘密字段脱敏，损坏配置不能被空对象覆盖。修改影响活动会话时说明何时生效；需要 reload 时不偷偷终止任务。更新失败保持原版本可用，清楚区分“已保存”“待重新加载”“正在运行”。

## 11. 生命周期与异常恢复（I10；E10）

| 情形 | 必须发生的行为 |
| --- | --- |
| 关闭窗口 | 默认隐藏至托盘，首次解释后台继续；任务/审批状态仍可查看。 |
| 托盘打开 | 恢复同一实例，不产生第二个调度器或服务器。 |
| 明确退出 | 停接新任务、停止调度、取消审批/agent/browser、刷新记录，然后回收本应用的进程树。 |
| 正在执行的外部动作无法撤销 | 保留实际结果并说明取消只阻止后续动作，不冒充回滚。 |
| 超过 10 秒仍未正常停止 | 只终止本应用拥有的进程树，记录 interrupted；不得按进程名杀死其他 Node/Chrome。 |
| 崩溃/断电后启动 | 以持久记录恢复列表，未完成任务标 interrupted，用户显式恢复；不重放工具或已接受的消息。 |
| SSE 断线/重连 | 读取服务端状态并去重事件；不重新执行 prompt。 |
| 模型限流/网络失败 | 可取消的退避与可重试状态；鉴权错误不无限重试，不因失败切换到别的付费提供商。 |
| 文件变更冲突/磁盘满/无权限 | 保留旧文件与用户草稿，明确失败；不能报告为已保存。 |
| 数据升级 | 版本化、原子写、先备份；不认识的较新格式可只读/拒绝升级，不清空。 |

进程关闭顺序是新实现的集成验收，不以现有 orphan detector 存在即推断已经满足全部条目。

## 12. 验收、性能与正式发布（I12；E11）

验收矩阵中的每项需要可定位的测试/实测记录：

| ID | 验收场景 | 可观察结果 |
| --- | --- | --- |
| A01 | 无模型的新安装 → 配置自带模型 → 新项目首轮 | 引导可完成；真实流式结果与产物保存。 |
| A02 | CJK/长输入/重复点击/发送途中断网 | 不误发送、不丢草稿、不重复任务。 |
| A03 | 流式生成时向上阅读/切会话/恢复 | 阅读位置、草稿和状态保持一致。 |
| A04 | 越界/junction/删除/参数变更/审批重放 | 执行前正确阻止或要求新审批，拒绝后无副作用。 |
| A05 | 4 个 agent、队列、同时写、停止父任务 | 不越权、不重复写、不遗留子任务。 |
| A06 | 托盘/睡眠/DST/退出期间的定时任务 | 记录准确，最多一次补跑，退出不运行。 |
| A07 | 浏览器研究/交互审批/手动登录/下载/取消 | 真实受控页面，外部动作审批有效，profile 隔离。 |
| A08 | MCP/skills/插件添加与损坏配置/更新失败 | 真实启停、错误可修复，未授权不执行。 |
| A09 | 关闭/退出/崩溃/重启/升级 | 历史和设置保留，没有旧任务自动重放或本应用孤儿进程。 |
| A10 | Windows DPI/主题/键盘/缩小窗口/中英文 | 无不可操作控件、焦点丢失或关键文字缺失。 |
| A11 | 干净 Windows 安装、旧版覆盖、卸载/重装 | 独立身份、保留用户数据选项、Pilaude 更新来源正确。 |
| A12 | 产物、Diff 和代码工具输出 | 可打开、复制、保存，路径和内容与执行结果一致。 |

性能是工程验收目标而非已测结论：Windows 11 x64、4 核/16GB/SSD、发布构建，禁用模型网络耗时后，冷启动至可操作 P95 ≤5 秒，常用输入与面板交互 P95 ≤100ms；10,000 条文本消息的测试会话在 2 秒内显示可交互的首屏。记录包体、后台空闲/活动峰值内存和基线机器；2 小时任务/切会话耐久测试无崩溃、重复调度或持续无界增长。若目标不达标，附 profile 后调整实现或明确修订目标，不删除坏样本。

Windows 正式发布须有自己的安装包签名及更新签名、版本/组件清单、校验值、第三方声明、帮助/恢复说明和干净机器验证。签名服务/证书与真实模型账号属于外部输入；未提供时可以交付可验证的开发安装包，但不能称已完成正式发布。Windows 签名依据 [Tauri 官方流程](https://v2.tauri.app/distribute/sign/windows/)。

## 13. 追踪和变更

每项实现/测试映射到 I、E、A 编号。工程默认值可随实测修订，记录原因、用户影响和替代选项；用户确认的 I01–I12 不能为方便实现而静默缩减。任务进度记录在 Plan，不把未执行的验收写成通过。
